# MLBB Hub 担当エージェントへの引継ぎ（2026-09-08）

ポータル（hub-game.com）を担当しているセッションから、MLBB Hub
（`C:\Users\81901\Desktop\モバレサイト`）を公開する担当への申し送り。

運営者の方針は「**モバレを先に公開する。競合が現れる前に**」。
ポータル側は受け入れ準備を済ませてあるので、そちらは MLBB 本体に集中してよい。

## 1. 結論から: ポータル側でやることは無い

`mlbb.hub-game.com` が 200 を返すようになったら、ポータルの
[`src/data/highlights.ts`](../src/data/highlights.ts) の **1行を書き換えるだけ**で載る。

```ts
export const SITE_LOCALES: Record<HighlightSite, string[]> = {
  wildrift: ['ja', 'en'],
  hok: ['ja', 'en'],
  mlbb: [],        // ← ここを ['ja'] にする
};
```

**MLBB は日本語のみで公開する前提にしてある。**（2026-09-08 に MLBB 側 ee30f3e で
英語ページを廃止。同名の英語サイト mlbbhub.com が先にあり、内容も重なるため。
711ページ→359ページ、/en は /ja へ 308）。

そのためポータルは真偽値ではなく**対応言語の配列**を持つ。空配列は未公開。
`['ja']` にすれば日本語のポータルにだけ出て、英語のポータルには出ない。
英語の読者を、読めない日本語だけのサイトへ送らないための区別。

参照側は用途で2つに分かれている。

| 関数 | 用途 |
|---|---|
| `liveSites()` | 言語に依らないもの。robots.txt の sitemap 列挙、JSON-LD の sameAs、`/api/latest` の取得先 |
| `liveSitesFor(locale)` | 読者が踏むもの。最新データ表の列、最新パッチの注目カード |

`['ja']` にして実際の出力を確認済み。

```
日本語の表  項目 | Honor of Kings | Wild Rift | Mobile Legends
英語の表    Aspect | Honor of Kings | Wild Rift
robots.txt  4本すべて（サイト自体は存在するので言語に依らず載せる）
```

これ1箇所で次のすべてが切り替わる。コミット `d507214` と `80df316` で実装済みで、
実際にフラグを立てて日英とも表示を確認してある。

| 切り替わるもの | 実装 |
|---|---|
| `robots.txt` の Sitemap 列挙 | `src/app/robots.ts`（言語に依らない） |
| JSON-LD の `sameAs` | `src/utils/jsonld.ts` |
| `/api/latest` の取得先 | `src/lib/sisterSites.ts` |
| トップの「タイトル別の最新データ」表の列 | `src/components/TitleSnapshot.tsx`（言語別） |

**フラグを立てる前に `mlbb.hub-game.com` が 200 を返すことを確かめること。**
未公開のドメインを出すと、死んだリンクを読者と Google の両方に見せることになる。
hub-game.com はいま AdSense のポリシー違反を受けている最中で（4節）、
判定はドメイン単位なので切れたリンクを増やす余裕は無い。

## 2. MLBB 側に用意してほしいもの

### 2-1. `/api/latest`（必須ではないが、あると表が自動で埋まる）

仕様は [SNAPSHOT_CONTRACT.md](./SNAPSHOT_CONTRACT.md) にある。HoK と Wild Rift は
両方とも対応済みなので、動いている実物を見られる。

```bash
curl -s https://hok.hub-game.com/api/latest | jq .snapshot
curl -s https://wildrift.hub-game.com/api/latest | jq .snapshot
```

返さなくてもポータルは壊れない。**MLBB の列は「—」が出るだけ。**
静的値の控えを用意していないのは意図的で、実データの裏が無い数字を手で書いて
表に出すくらいなら、無いことを見せたほうがよいという判断。

`snapshot.catalog.arcana` には**エンブレムの数**を入れる。3つ目の枠の呼び名が
タイトルで違うだけで（HoK はアルカナ、Wild Rift はルーン）、キー名は共通。
ポータル側が「エンブレム◯種」と出し分ける。`src/data/emblems/` を見て決めた。

`snapshot.site.updatedAt`（サイト自体の最終更新日）は**任意**。返すと表の
「サイトの最終更新日」の行が埋まり、返さなければその欄が「未公開」になる。

### 2-2. ポータルに置く素材（これが無いと出せないもの）

| 要るもの | 置き場所 | 備考 |
|---|---|---|
| バナー画像 | `public/images/games/mobile-legends.jpg` | 他2枚と同じ比率。**公式アートを外部CDNへ直リンクしない**（相手の都合で壊れるため自サイトにホストする、というのが既存2枚の方針） |
| ゲームカードの紹介文（日英） | `messages/{ja,en}.json` | 既存の Wild Rift / HoK のカードと同じ粒度 |
| `guides/mobile-legends` の記事本文 | 同上 + `src/data/articles.ts` | 既存の `honor-of-kings` / `wild-rift` の記事に相当するもの |

トップのゲームカードは、いまは2枚が手書きの JSX で並んでいる
（`src/app/[locale]/page.tsx`）。ここだけは素材が揃ってから作る。**素材が無い状態で
枠だけ作らないこと。**

## 4. AdSense の状況（判断に効くので必ず読むこと）

2026-09-08 に `hub-game.com` が**不承認**になった。理由は「有用性の低いコンテンツ」。
理由文の全文と経緯は [ADSENSE_REVIEW_LOG.md](./ADSENSE_REVIEW_LOG.md) にある。

**この判定は MLBB にも及ぶ。** AdSense はサブドメインを親ドメインと別のサイトとして
扱えないため、`mlbb.hub-game.com` は公開した時点で `hub-game.com` の判定に含まれる。

> 【サイト】ページでは、既存のサイトに含まれているサブドメインの追加と管理ができなくなります。
> — https://support.google.com/adsense/answer/12170421?hl=ja

再審査は **2026-09-14 以降**（リクエスト回数の上限に達しているため、それまで申請できない）。

### ここから導かれる注意

**テンプレートから量産したページを増やさない。** 「有用性の低いコンテンツ」は、
1件のデータを流し込んだだけのページが大量にある状態を名指しする。URL を増やすこと
自体は答えにならない。

Wild Rift 側は今日この判断を実際に使っている。アイテムの個別ページを作る際、
素材アイテム52件を「ステータス1〜2行と価格しか書けない」という理由で落とし、
残す100件には実測の採用データと共起を足して一覧の切り出しにならないようにした。
MLBB はレシピを54件持っているので、「何から作るか」が書ける点で有利。

## 5. HoK 側の失敗から持っていける教訓

同じテンプレートから育った3サイトなので、同じ穴が空いている可能性がある。

### 5-1. 出所を示せないデータを「公式」と称さない

HoK は「公式の能力評価」として4軸（生存・攻撃・スキル・操作難度、各1〜10）を
出していたが、追跡したところ**初回コミットから94体が一度も更新されておらず、
取得手順の記録がどこにも無く、公式 API にも該当フィールドが無かった。**
116体中30体は値が壊れてもいた。2026-09-08 に表示ごと廃止した（HoK の `02d0435`）。

逆に Wild Rift は同種の「公式の適性」に出所を明記し（「役割・難易度はグローバル版
公式サイト、推奨レーンは中国版公式サイトより」）、**ゲーム内と食い違う8体を名指しで
開示している。** これが正しい形。MLBB も、出所を書けないデータは出さないか、
書けないと明記する。

### 5-2. 数字を出すなら分母と欠けを書く

Wild Rift はルーンの読み取りが 1,180枠中 553枠（47%）欠けていたので、それを
ページに明記した。欠けを出さずに「N体が組んでいる」と書くと、実際より少ない数を
採用実績として読まれる。

HoK の 227構成は 1,362枠すべてが埋まっていたので注記不要だった（実測して確認）。
**MLBB の 264構成も、まず欠けの有無を数えること。**

### 5-3. sitemap の `lastmod` を全ページ同じ日付にしない

HoK は 298 URL すべてが同じ日付で、しかもプッシュのたびに当日へ動いていた。
規約やプライバシーポリシーまで毎回「今日更新した」と申告する形だった。

> Google uses the `<lastmod>` value if it's consistently and verifiably accurate.
> — https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap

2026-09-07 にページ群ごとの日付へ直した（HoK の `99763e6`）。1種類→17種類。
固定ページは専用の `updatedAt` を新設、ガイドは既存のページ別日付、版ごとの
パッチノートは URL の日付をそのまま使う、という分け方。

### 5-4. 「未確認」と書いたものを断定形で公開しない

HoK はボスの出現時刻を社内の記録で「2:00 か 4:00 か要確認」としながら、ガイドでは
断定形で 2:00 と出していた。2026-09-07 に運営者がゲーム内で確認し、**どちらも 4:00**
だと判明。ポータルにも同じ誤りが伝播していて、日英12箇所を直した（`d158a41`）。

外部の攻略記事は 2:00 と 4:00 が混在している。参照して書き戻さないこと。

  英語版を書いて日本語サイトへ送るのは、読者にとって行き止まりになる
