# 案D の実行計画（WR とポータルを閉じ、HoK と MLBB の2つで運用する）

2026-10-31 に運営者が「案Dで進める」と決めた。WR は需要が薄く、更新の負担が大きい。
WR を残して更新だけ止める案と、WR を別ドメインへ移す案は、運営者がやらないと決めている。

検証（`scratch/analysis_1031/d_check/result.json`）の結論は「条件つきで不利にならない」。
ページを消すこと自体を減点する記述は、AdSense にも Google 検索にも無かった。危ないのは後始末の漏れだけ。

## 決めたこと

| 項目 | 決めたこと | 理由 |
|---|---|---|
| WR の閉じ方 | WR のリポジトリから、全パスに 410 と `X-Robots-Tag: noindex` を返す版を push する（W-b） | Cloudflare の管理画面と DNS に触らずに済む。開け直すときもタグへ戻して push するだけ |
| 旧 wildrift.hub-game.com | Redirect Rule は残す。301 のあと 410 に着く | ルールだけ消すと、旧サブドメインがエラーを返す |
| ポータル | Worker とカスタムドメインは残し、ページだけを閉じる。28 URL は 404 にする | ポータルの Worker が apex の DNS の持ち主。外すと /hok と /mlbb も止まる |
| `/` | 転送せず、運営者 HUB-GAME の1ページ（200）にする。広告のコードは載せない | サイト名とファビコンは `/` で1つに決まる。HoK へ送ると MLBB の検索結果にも HoK の屋号が出る。入口だけの画面への広告はポリシーで認められていない |
| `/ja`・`/en` | `/` へ 302 で送る | 301 はブラウザに残り、開け直す妨げになる |
| 1対1の記事 | `/ja/guides/honor-of-kings` は `/hok/ja/guide` へ、`/ja/guides/mobile-legends` は `/mlbb/ja/guide/basics` へ 301 で送る | 中身が対応するページだけに張る。ほかを関係のないページへまとめて送ると、ソフト404になる |
| HoK・MLBB のフッター | WR へのリンクは外す。ポータルへのリンクは「運営: HUB-GAME」として `https://hub-game.com/` に向け直す | `/` は運営者のページとして 200 で残る。外すより、運営者のページへ向けたほうが同じ運営だと分かる |
| 構造化データ | `/` に Organization（`https://hub-game.com/#organization`）を置き、HoK と MLBB の publisher はその @id を指す | 屋号が4つあり、組織も別々だった。1つにそろえる |
| 所有権の確認タグ | `google-adsense-account` の meta を、HoK・MLBB の layout と `/` に入れる | 今はポータルのページにしか無い。AdSense のコードは HoK・MLBB の本番に入っている（10/31 に確認） |
| HoK の Tier 表 | 上部は触らない | 直近7日のクリックの7割がこのページで、主な検索語は1位・クリック率約7割。表を下げると、スマホでは1画面目から表が消える |

## 順番

順番を誤ると本番が壊れる。今のポータルのビルドは、WR の `/api/latest` が取れないと止まる（`src/lib/sisterSites.ts`）。
WR を先に閉じると、WR へのリンクを含むポータルの古い版が本番に残る。

## サイトごとの作業

### HoK（オナキンのセッション）

- フッター（`Footer.tsx` 20・25行目）: WR の行を外す。ポータルの行は「運営: HUB-GAME」で `https://hub-game.com/` に向け直す
- トップ右上の HUB-GAME の札（`HomeClient.tsx` 183行目）: `https://hub-game.com/` へ向け直す
- リンク集（`links/page.tsx` 84行目と、日英の messages の `Links.useful`）: ポータルの行を外す。節が空になるなら節ごと外す
- JSON-LD（`[locale]/layout.tsx` 109行目）: publisher を `https://hub-game.com/#organization` の @id にする。sameAs の `https://hub-game.com/` は外し、X を残す
- `[locale]/layout.tsx` の metadata に `google-adsense-account`（`ca-pub-7201202773518258`）を足す
- about に「運営者・掲載方針・データの確かめ方」の節を足す。素材はポータルの about の運営者の紹介と掲載方針（「未確認は未確認と書く」）。プレイ歴などの体験は、運営者に確かめるまで書かない。10/28 に外した訂正の記録は、運営者の指示が無い限り戻さない
- `scripts/audit.mjs` に検査を足す。`/wildrift` へのリンクと、ポータルのページ（`/ja`・`/en` とその下）へのリンクを止める。`https://hub-game.com/` そのものは許す
- 最後に `npm run touch:updated`。コミット前に tsc・eslint・audit・build を通す

### MLBB（モバレのセッション）

- フッター（`Footer.tsx` 8・9行目）: WR の行を外す。ポータルの行は「運営: HUB-GAME」で `https://hub-game.com/` に向け直す
- リンク集（`links/page.tsx` 50・56行目）: ポータルと WR の行を外す
- JSON-LD（`[locale]/layout.tsx` 124行目）: HoK と同じく publisher を @id にし、sameAs の `https://hub-game.com/` を外す。WebSite の alternateName から旧名 `MLBB Hub` を外す
- metadata に `google-adsense-account` を足す
- about に、HoK と同じ「運営者・掲載方針・データの確かめ方」の節を足す。227・277行目の「ほかのゲームの攻略データサイトも hub-game.com で運営」は、HoK の名前を出す文にする
- 入口: トップの h1 にゲーム名（モバイル・レジェンド）を入れる。トップの導入文の「公式サイトの133体分のデータと…まとめています」を、自前の中身（133体の立ち回り、相性の理由、パッチの解説）から始まる文に替える。meta description は検索結果の表示文が変わるので、「公式データのまとめ」という名乗りだけを外し、Tier・勝率の語は残す
- `scripts/audit.mjs` に HoK と同じ検査を足す。最後に `npm run touch:updated`。コミット前に4つを通す

### WR（ワイリフのセッション）

- 閉じる直前の main に `wr-final-2026-11` のタグを打つ
- `worker/gone.js` を足す。どのパスにも 410 と `X-Robots-Tag: noindex` を返し、本文は HoK と MLBB へのリンクだけの短い案内にする。広告のコードは載せない
- `wrangler.jsonc` は main を `worker/gone.js` に替え、assets を外す。routes（`hub-game.com/wildrift*`）は残す
- `package.json` の build を軽い処理に替える。prebuild の audit が落ちると、前の版（全ページ 200）が本番に残る
- `worker/entry.js` は `hub-game-rules` から配っているので触らない
- push の前に、手元でビルドが通ることを確かめる

### ポータル（このセッション）

- `/` を運営者の1ページにする。中身は WebSite と Organization の構造化データ、運営者の紹介と掲載方針、HoK と MLBB への入口、`google-adsense-account` の meta。広告のコードは載せない
- 28 URL を書き出しから外す。コードは `portal-final-2026-11` のタグに残る
- `_redirects`: `/ja`・`/en` は `/` へ 302、上の1対1の2本だけ 301
- robots.txt の Disallow は `/hok/api/latest`・`/mlbb/api/latest` だけにし、Sitemap は HoK と MLBB の2本にする。sitemap_index.xml も2本にする。`/sitemap.xml` は出さない
- `sisterSites.ts` と GitHub Actions の `refresh-sister-data` を止める
- 404 画面は HoK と MLBB への入口だけにし、広告のコードは載せない
- 残すもの: ads.txt、sw.js、`wrangler.jsonc` の routes、Worker、`workers/legacy-sw`
- `scripts/audit.mjs` を新しい形に直す（ads.txt の pub ID、routes のカスタムドメイン、robots に `/wildrift` が無いこと）
- AGENTS.md を「ドメイン直下の持ち物だけを受け持つ」形に書き直す

## 運営者の作業

1. **今すぐでよい**: 旧デプロイ4つを止める。削除ではなく、一時停止か閲覧の保護をかける（削除すると名前を他人に取られうる）
   - Vercel の `wildrift-site`、`hub-game-portal`、`honor-of-kings-site`
   - Cloudflare Pages の `mlbb-site`
   - 4つとも 10/31 に 200 を返し、同じ pub ID を載せていた。`hub-game-portal.vercel.app` は 10/25 のコミットを含んでおり、Vercel の Git 連携がまだ生きている。止めるときは Git 連携も切る
2. **WR を閉じたあと**: Search Console（`sc-domain:hub-game.com`）で、WR とポータルと旧 `wildrift.hub-game.com` のサイトマップを削除し、`sitemap_index.xml` を出し直す。`https://hub-game.com/` の接頭辞は、削除ツールに絶対に入れない
3. **最後の push から2週間以上あけて**: 再申請する。目安は 11/20 前後。申請の前に、ポータルのセッションが本番の確認をやり直す（リンク0件、410、直下のファイル、`/` と 404 画面に広告のコードが無いこと、確認タグ）。HoK と MLBB の登録済みの件数が、案Dの前より減っていないことも確かめる

11/1 には再申請しない。分析と案Dの検証の両方が、同じ結論だった。

## 案Dのあとに回すこと（再申請を待たせない）

- HoK の立ち回りを、MLBB と同じ3節（序盤・中盤以降・集団戦）にする。決まりは「1つの事実は1ページに1回」。HoK の立ち回りの数値は、93% が同じページのスキル説明と重なっていた。書き足すのではなく、重複を消す
- WR の「全ランク帯と上位帯で勝率が違う」分析の作り方を、MLBB の Tier 表へ移す（公式ランキングのランク帯6段で同じ計算ができる）。HoK Camp の統計にはランク帯が無いので、HoK へは移せない
- ポータルの用語対応表と「最初の1試合で事故る5点」を2タイトル版に縮め、HoK か MLBB のどちらか一方にだけ置く

## 開け直すとき

WR は `wr-final-2026-11`、ポータルは `portal-final-2026-11` のタグへ戻して push すれば、同じ URL で開く。
Search Console のサイトマップは出し直す。索引・順位・外部リンクの評価は取り直しになる。
