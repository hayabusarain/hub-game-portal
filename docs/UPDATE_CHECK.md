# 更新チェック（合い言葉「チェック」）

運営者が「チェック」と言ったら、ポータルのセッションがこの手順で HoK と MLBB の更新を確かめさせる（2026-10-31 に運営者が決めた）。
ポータルのセッションは指示と確認の役で、データの取得と書き直しは各サイトのセッションが行う。

## 流れ

1. ポータルのセッションが、オナキン（HoK）とモバレ（MLBB）のセッションへ、下の「送る文」を SendMessage で送る
2. 各セッションが確かめて、更新があれば直し、4つの検査（tsc・eslint・audit・build）を通してコミットする。push はしない
3. ポータルのセッションが、届いた報告と差分を確かめ、運営者に1つにまとめて報告する
4. 運営者が各セッションで push を承認する（各サイトの決まりで、ほかのセッション経由の承認では push しない）
5. push のあと、ポータルのセッションが本番を確かめる

## 送る文

```
【ポータルから】更新チェックです（合い言葉「チェック」、手順はポータルの docs/UPDATE_CHECK.md）。
次の4つに、前回の取得のあと更新が来ていないか確かめ、来ていれば直してコミットまでしてください。push はしないでください。

1. Tier 表の統計（HoK は HoK Camp、MLBB は公式ランキング）
2. パッチノート（新しい版が出ていれば、版のページと解説）
3. イベント（期間が終わったもの、新しく始まったもの。月の見出しが古くなっていないか）
4. 新しいヒーロー

決まり:
- 取得の手順は、このサイトの AGENTS.md とメモのとおりにする
- 外部知識で埋めない。確かめられないことは「未確認」と書く
- 中身が変わっていないのに日付だけ上げない
- ゲーム内の撮影が要るものは書き足さず、「運営者の撮影待ち」として一覧にする
- 4つの検査を通してからコミットする

終わったら「ポータル」宛てに、次を送ってください:
- 4つそれぞれについて、更新の有無と、確かめた出どころと日付
- 直したファイルとコミットのハッシュ（直さなかったなら「変更なし」）
- 運営者の撮影待ちの一覧
```

## ポータルのセッションが確かめること

- 報告の数字が、出どころの日付と合っているか
- 差分に、日付だけの更新や、閉じた WR・ポータルの記事へのリンクが入っていないか
- push のあと、本番で更新が出ているか（Tier 表の取得日、パッチの版、イベントの見出し）

5時間枠を2つのセッションで同時に使うので、始める前に get_usage で残りを見る。8割を超えていたら、運営者に伝えてから始める。
